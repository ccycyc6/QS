## 2. 实测数据

### 2.1 综合（synthesize + dev_map，PDS 2025.2）

| 配置 | LUT | FF | DRM | APM | LUTRAM | IO |
|---|---|---|---|---|---|---|
| 视觉基线 | 78,758（49.29%） | 100,825 | 222.5（53.61%） | 261（35.27%） | 1,318 | 136 |
| + RV 核（随机指令流） | 86,832.5（54.34%） | 107,086 | 249（60.0%） | 281（38.0%） | 1,990 | 136 |
| + RV 核（真实固件 39 条） | 86,720（54.27%） | 107,209 | 240.5（57.95%） | 281 | 1,990 | 136 |
| **+ RV 核 + 控制器串口** | **86,844.5（54.35%）** | 107,387 | 240.5 | 281 | 1,990 | **137** |

**结论**：视觉 + 核 + 串口可以同进一个位流，仍有余量。控制器通路只多 124 LUT；RV 核约 8k LUT。

### 2.2 完整 PnR（仅视觉基线，未含核）

| 资源 | 用量 | 占比 |
|---|---|---|
| CLMA | 18,369 / 30,075 | **62%** |
| LUT | 62,727 / 120,300 | 53% |
| FF | 78,293 / 240,600 | 33% |
| DRM36K | 194 / 415 | 47% |
| APM | 261 / 740 | 36% |
| BKCL | 5 / 10 | 50% |
| GPLL | 4 / 10 | 40% |

- 时序：**TNS = 0，WNS = +116 ps**（裕量很薄）
- 耗时：compile 48 s + synthesize 5 m 24 s + PnR 约 10 m + 位流 1 m 2 s = **17 m 23 s**；重出一次含条件端口的版本为 **20 m 48 s**，峰值内存 5.0 GB
- 位流：PnR 产物不入库（约 9 MB）；仓库不保留预置位流，需要时本地重出。

### 2.3 ARES 核单独实测（用于判断能否共位）

| 配置 | LUT | FF | APM | DRM |
|---|---|---|---|---|
| 含三个 CoreMark 加速器 | 8,164.5 | 6,569 | 20 | 86.5 |
| 去掉加速器 | 5,365.5 | 5,045 | 4 | 80.5 |
| **加速器成本** | **2,799** | **1,524** | **16** | **6** |

结论：三个加速器只占 1.75% LUT，“砍加速器就能瘦身”不成立；真正占资源的是
32 KiB IROM + 256 KiB DRAM 阵列（80.5 个 DRM 里的 72 个）。

## 3. 踩过的坑

| # | 现象 | 原因 | 教训 |
|---|---|---|---|
| 1 | 综合出 LUT = 0 | IROM 全零，指令流恒定，整片常量传播 | 测面积必须给非恒定指令流 |
| 2 | 只 +2,327 LUT（低估 3.5 倍） | IROM 只有两条指令交替，数据通路被大量剪枝 | 用随机或真实固件 |
| 3 | 核没被例化 | rv_cfg.vh 被同目录空版本抢先命中 | 头文件不要和引用者放同一目录 |
| 4 | ARES 探针 LUT = 0 | GTP_GPLL 在 2025.2 下当黑盒，时钟不可见 | 面积探针要把 PLL 换成直通 |
| 5 | 固件编译失败 | 相对路径加反斜杠被 ld 拒绝；缺 _program_start | 用绝对正斜杠路径 + 自带链接脚本 |
| 6 | 宏定义写成裸 define | PowerShell 双引号里反引号是转义符 | 写 Verilog 宏用文件写入 |

## 4. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D-001 | 工具链用 **PDS 2025.2-SP3**，不装 2022.2 | 实测能吃下全部源码，综合 0 error；代价是数字不与作者记录直接可比 |
| D-002 | fpga/ 保持原工程结构 | .pds 内全是相对路径，重排会破坏引用 |
| D-003 | 只保留 195.7 MB 必需文件 | 原目录 1.3 GB，600+ MB 是构建产物 |
| D-004 | 核采用**档 2**：裁剪版 ARES | 完整 SoC 含 256 KiB DRAM 阵列，与视觉共位不划算 |
| D-005 | 纳入 Git，模型数据一并入库 | 保证仓库自包含 |
| D-006 | 核定位为**小调度器（档 B）** | 只做帧级取数/去抖/放行，不碰数据通路；开关 WITH_RV |
| D-007 | 控制器与视觉**共位一个位流** | 实测只多 124 LUT，没有必要拆两块板 |
| D-008 | 手势训练链放 `pcvision/gesture/`，环境放仓库外 `../gesture-env` | torch/CUDA 与缓存数 GB，隔离后一条 `cleanup.sh` 即可腾空；仓库只留脚本 |
| D-009 | 训练归一化改为 `(x-128)/128` | 与 RTL/`hw_emulate` 的 `int-128` 一致，float 与位精确结论可直接对照 |
| D-010 | 手势=静态分类，动作=PC 时序层 | 现有 RTL 无时序单元；hold/swipe 先由 `actions.py` 产生，接口与板端 argmax 输出一致 |
| D-011 | 平台收成单一入口 `gesture.sh`，环境仍在仓库外 `../gesture-env` | 之前多个脚本/文档入口太乱；日常只记一个命令，仓库只留代码 |
| D-012 | 线 B 先 PC 本地跑通，板子/RV/HDMI 暂停 | 先验证模型/动作/实时效果；板子迁移等效果满意后再做 |
| D-013 | 动作层加 SEQUENCE，且默认接受负 logit | 模型输出是原始 logit（常为负）；原来 conf_threshold=0 会把所有帧过滤掉 |
| D-014 | 镜像做成开关：默认原始非镜像，勾选=自拍镜像 | 预览和新录制一起翻转；已有数据方向不变，避免悄悄改数据 |
| D-015 | 偏置量化按累积激活尺度 `c_in` 修正 | 只按 1/scale 缩放会让 7 类模型全判背景（int 11%）；修正后 float/int 均 89.04% |

## 7. 澄清：核不是「5 级」

项目文档（包括 ARES 原 README 和我们的早期文档）一直写「5 级」，但那来自上游 Chisel 分支名
npc 5-stage-pipeline（commit 1d839c86），不是实际 RTL 结构。

实际结构（依据 Mundus.sv 中 7 组 *_io_in_bits_r_* 寄存器边界）：

| 流水级 | 边界寄存器组 | 备注 |
|---|---|---|
| IF  | （无独立输入寄存器） | 取指由 IFU/I-Cache 完成 |
| ID  | IDU_io_in_bits_r_*（4） | |
| IS  | ISU_io_in_bits_r_*（26） | 发射 / 寄存器读 |
| EX1 | EXU_io_in_bits_r_*（29） | ALU / BRU |
| EX2 | exu_ex2_io_in_bits_r_*（13） | 乘除 / CRC 低 4 bit |
| EX3 | exu_ex3_io_in_bits_r_*（11） | 乘除多周期 / CRC 高 4 bit |
| EX4 | exu_ex4_io_in_bits_r_*（9） | 写回数据汇聚 |
| LSU→WB | WBU_io_in_bits_r_*（27） | LSU 与 WBU 共用这一拍 |

- **寄存器拍数：8**（IF / ID / IS / EX1 / EX2 / EX3 / EX4 / WB）；
- **功能单元数：9**（IFU/IDU/ISU/EX1/EX2/EX3/EX4/LSU/WBU）；
- IFU 与 LSU 没有独立的输入寄存器组，所以它们不单独构成一拍。

**结论**：叫「5 级」是命名沿用，不准确；按寄存器边界是 **8 级**，按功能单元是 **9 级**。
对外表述建议统一为「单发射、8 级流水（9 个功能单元）」。

## 8. 上板流程（历史车牌视觉线，不用于手势）

> 本节是历史车牌 demo 的烧写/排错流程，保留作硬件参考；手势线上板另做，
> 当前 PC 本地阶段不执行。

### 8.1 烧写

```
# 方式一：脚本（JTAG）
powershell -File tools/program.ps1 -Bitstream bitstreams/<xxx>.sbit

# 方式二：PDS GUI -> Tools -> Download -> 选 .sbit -> Download to SRAM
```

下载到 SRAM 即可（掉电丢失），不需要烧 Flash。

### 8.2 接线

| 端口 | 连接 |
|---|---|
| HDMI IN | 信号源，**必须 1280×720@60**（1650×750 时序，74.25 MHz） |
| HDMI OUT | 显示器 |
| JTAG | Pango 下载器 |
| 电源 | 12V |

### 8.3 预期现象（按顺序）

| # | 现象 | 含义 |
|---|---|---|
| 1 | 复位后 LED1（**C18**，`ddr_init_done`）亮 | DDR3 校准通过 |
| 2 | 显示器出现 720p 画面（原图环出） | HDMI 收发链路正常 |
| 3 | 画面中出现检测框 | YOLO 检出候选 |
| 4 | LED0（**A20**，`led_int`）亮 | LPRNet 认出了字符（锁存型，识别到一次后常亮，复位清零） |

### 8.4 排错顺序（从后往前查）

| 现象 | 先查 |
|---|---|
| 全黑 / 无信号 | MS7210 未配置：`hd_scl`=K22 / `hd_sda`=K23 是否接反；`rstn_out`(G25) 是否 1ms 后释放；`pixclk_out`(T24) 是否 74.25 MHz；输入是否真为 720p60 |
| 有画面无框 | 输入分辨率；`CONF_THRESH`（`hdmi_loop.sv` 里 8'h40，可试 0x20/0x60） |
| 有框无字符 | 看 LED0：不亮说明 LPRNet 链路没出字符，查 crop 触发与 `lprnet_out_valid` |
| 框与画面不同帧 | `DDR_READ_START_LINE`（默认 6）；LED1 是否亮 |
| 画面撕裂/闪烁 | box/crop 时序问题，见 `fpga/doc/改动.md`；确认 `MAX_BOX_NUM`=6 与 crop buffer 深度匹配 |
