# 决策记录

## D-001 工具链：使用 PDS 2025.2（不用 2022.2-SP6.4）

**日期**：2026-11-11
**状态**：已采纳

### 背景

加速器工程由 Fabric Compiler **2022.2-SP6.4** 生成，`复现指南_MES2L676-200HP.md` 写的是
“必须这个版本”。本机只装了 `D:/Pango/PDS_2025.2-SP3-EN-ads`。

### 决定

用 **2025.2-SP3** 做复现与后续开发，不安装 2022.2。

### 依据

实测 2025.2 能完整吃下这套源文件：37 个 RTL + 4 个 IP（ms72 / PLL / ip_fifo / ddr3_test）
全部编译通过，综合到映射阶段 0 error。没有出现工程版本拒绝、IP 不兼容或语法不支持。

### 后果（必须记住）

1. **资源与时序数字不能和作者记录直接比较**。作者记录的全链路是 LUT 51.76%、DRM 61.93%、
   APM 37.70%（2022.2 下测得）。2025.2 的综合结果会不同，从今天起**以我们自己的实测为基线**。
2. **位流不能保证与归档位流一致**。归档定 `bitstreams/s3h_video_fb_top.sbit` 的 sha256 前 16 位
   是 `141344AD702160D0`；我们自己生成的位流会有新的 sha256，需要重新记录。
3. `prj_pds/hdmi_loop.pds` 里记录的综合器路径指向 `C:/pango/PDS_2022.2-SP6.4/...`，
   我们改用**脚本化流程**（`tools/build_full.tcl`）绕开工程文件，不再依赖 GUI 工程。

### 替代方案（未采纳）

- 安装 2022.2-SP6.4：可与作者数字对齐、位流可复现，但要多装一套工具链，且旧版本在不同
  Windows/驱动环境下更容易出问题。

## D-002 工程组织：fpga/ 原样部署，不重排目录

**日期**：2026-11-11

`prj_pds/hdmi_loop.pds` 中所有源文件都是相对路径（`../rtl_pds/...`），重排目录会破坏引用。
因此 `fpga/` 下保持 CNN_FPGA 的原始结构，新增内容只放在
`rtl_pds/target/`（新 RTL）、`sim_pds/`（新 TB）、`tools/`（脚本）三处。

## D-004 采用「档 2」：裁剪版 ARES 核接入视觉工程

**日期**：2026-11-11
**状态**：已采纳（先备料，未接入）

### 背景

视觉工程实测：CLMA 62%、LUT 53%、DRM36K 47%、APM 36%，时序 WNS **+116 ps**。
余量：LUT 47%、CLMA 38%。

关键数据：去掉三个加速器的 ARES SoC 实测 **5,365 LUT / 5,045 FF**，其中 80.5 个 DRM
里 72 个是 32 KiB IROM + 256 KiB DRAM 阵列 —— **逻辑很便宜，贵的是存储器**。

### 决定

采用档 2：用自研 ARES 核，但砍掉 cache、DRAM 阵列、加速器、多核，只留控制面。

### 依据

| 档 | 面积增量 | 时序风险 |
|---|---|---|
| 1（另写最小 RV32I） | ~2–3% LUT | 低 |
| **2（ARES 裁剪）** | **~4–5% LUT、<10 DRM** | 中 |
| 3（完整 ARES） | +5.4k LUT、+80 DRM | 高（装不下） |

### 必须遵守的接入原则

1. **不碰 CNN 数据通路**（148.5 MHz 域、WNS 只有 +116 ps）；
2. 核跑**独立 50 MHz 域**，只用异步 FIFO 与 MMIO 寄存器跨域；
3. 用 `ifdef WITH_RV` 包住，随时能退回无核基线；
4. 核只做**控制面 + 文本面**：改阈值/ROI、生成 OSD 文本、时序后处理。
