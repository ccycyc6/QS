# 在盘古200Pro+（MES2L676-200HP）上复现本工程

> 目标板：小眼睛 盘古200Pro+ 开发板 / MES2L676-200HP，主控 PG2L200H-6IFBB676（工业级，与工程里的 -6FBB676 同一器件）。
> 本文对应当前仓库状态：顶层已经改成 200Pro+ 的 HDMI 输出方式，引脚约束已按 200Pro+ 重写。

---

## 0. 结论：能复现，差异只在 HDMI 这一块

已经逐项核对过，下面这些和 200Pro+ **完全一致**，不用动：

| 项目 | 工程中的值 | 200Pro+ 硬件手册 |
| --- | --- | --- |
| 主控 | PG2L200H-6FBB676 | PG2L200H-6IFBB676（同器件，I=工业级） |
| 系统时钟 `sys_clk` | 27MHz（`ms72` PLL 输入 27M → 输出 10M 做 I2C） | 板载 27MHz 单端有源晶振 |
| DDR3 参考时钟 | 125MHz 差分（`clk_p/clk_n`，周期约束 8ns） | 板载 125MHz 差分有源晶振 |
| DDR3 器件/位宽 | MT41K256M16 ×2，32bit，8Gbit | 2 片 4Gbit，共 32bit，8Gbit |
| DDR3 引脚 | 73 根（HSTL15） | 与官方 `3_4_HDMI_IN_DDR3_bin` 例程逐根一致 |
| 复位/按键/LED | `rst_n`=C22，`led_int`=A20 | 一致（A20 是 LED0，C18 是 LED1） |

**不一致的只有 HDMI：**

1. **HDMI 输出实现方式不同（关键）**
   - 原工程面向作者的 PG200K-mini 板：FPGA 直接输出 **TMDS 差分对**（`tmds_clk_p/n` + 3 对 `tmds_data_p/n`，共 8 根），板上没有发送芯片。
   - 200Pro+：FPGA 输出 **24bit 并行 RGB + DE/HS/VS + 像素时钟**（28 根），由板载 **MS7210**（I2C 0xB2）做 TMDS 编码后送 HDMI 座。
   所以原工程的 `rgb2tmds` 输出级在 200Pro+ 上根本无法工作，必须换成并行 RGB。

2. **HDMI 输入有 13 根引脚不同**（同为 MS7200，I2C 0x56，但底板走线不同）。

3. **I2C 引脚不同**：mini 板是 J14/J15，200Pro+ 是 `hd_sda`=K23、`hd_scl`=K22。

> 因此：**`bit_files/` 里的 `.sbit` 不能直接下载到 200Pro+**（引脚不同 + 输出方式不同）。必须按本文重新综合。

以上 1、2、3 已经在本仓库里改好了，见第 2 节。

## 1. 你需要准备的东西

- 盘古200Pro+ 开发板 + 12V 电源 + Pango 下载器（JTAG）
- 2 根 HDMI 线：PC/摄像头 → 板子 HDMI IN；板子 HDMI OUT → 显示器
- **视频源必须是 1280×720@60Hz（CEA 时序 1650×750，像素时钟 74.25MHz）**
  - 工程的 DDR 行缓冲、overlay 坐标、LPRNet 输入都按 720p 固定参数写死（`H_ACT=1280, V_ACT=720, H_TOTAL=1650, V_TOTAL=750`）。
  - 1080p / 720p50 / 1080i 都不行，会全黑或错位。Windows 里把显示模式设成 1280×720@60 即可。
- 软件：
  - **Pango Design Suite 2022.2-SP6.4**（必须这个版本；工程 `.pds` 里 IP 和综合器路径都按它生成）
  - ModelSim SE-64 2020.4（只做仿真时需要）
  - Python 3.x + `numpy scipy pillow opencv-python pyusb`（只有重新生成网络参数、比对数据时才用；仓库里已包含生成好的 `.mem/.vh`，可以先不装）

## 2. 仓库里已经为你改好的内容

### 2.1 `rtl_pds/hdmi_loop.sv`

- 输出端口由 `tmds_clk_p/n`、`tmds_data_p/n[2:0]` 改为：

  ```verilog
  output pixclk_out, output vs_out, output hs_out, output de_out,
  output [7:0] r_out, output [7:0] g_out, output [7:0] b_out,
  ```

- 删掉了 `rgb2tmds` 实例，改成和官方 `2_10_hdmi_loop` 例程一致的并行输出：
  像素时钟直连 `pixclk_in`；`vs/hs/de/rgb` 打一拍输出；`init_over`（I2C 配置完成）之前输出全 0，避免上电花屏。
- 内部原来的 `pixclk_out` 线网改名为 `pixclk_video`，避免和新的输出端口重名；PLL 保留（`clk_pe`=148.5MHz），`pix_clk_5x` 现在不再使用。

### 2.2 `prj_pds/hdmi_loop.fdc`

- HDMI 输入 28 根、I2C 2 根，按 200Pro+ 官方例程（`2_Demo/2_10_hdmi_loop`）的引脚重写；
- 删掉 `tmds_*`，新增 28 根并行 RGB 输出；
- DDR3 73 根、`clk_p/clk_n`、`sys_clk`、`rst_n`、`led_int`、`ddr_init_done` 全部保持原值；
- 原始 mini 板约束备份为 `prj_pds/hdmi_loop_200kmini.fdc`；
- 生成/校验脚本在 `tools/pinmap/`：
  - `make_proplus_fdc.py`：从 200Pro+ 官方例程的 `.fdc` 重新生成引脚约束
  - `check_pinmap.py`：检查「顶层端口 ↔ 约束引脚」是否一一对应、有无重复占用

### 2.3 仿真输入路径修复（重要）

原仓库 `rtl_pds/data_process/header/layer*.vh` 里的 `INPUT_FILE_PATH_LAYER*` 写的是作者机器上的绝对路径

### 3.1 为 Verilator 做的 RTL 适配（功能等价，已在 PDS 验证）

原来 `d_manager.sv` / `input_layer.sv` / `pe_page.sv` 里有"同一个变量在不同 generate 分支里
分别被 `assign` 和 `always_ff` 驱动"的写法。ModelSim/PDS 接受，但 Verilator 明确报
**Unsupported: Blocked and non-blocking assignments to same variable**；用 `-Wno-BLKANDNBLK`
压掉后虽然能编译，**建模却是错的**（表现为 CPI>1 的卷积层输出全错、整网出不了字符）。

现已改成逐位独立驱动：

| 文件 | 改动 |
| --- | --- |
| `d_manager.sv` | `D` 改由非压缩数组 `d_tmp` 逐位 `assign` 汇总 |
| `input_layer.sv` | `we_line_ram` 改为非压缩数组 |
| `pe_page.sv` | `D_delay` 改为非压缩数组 |

改完 Verilator 不再需要任何抑制开关，12 层 + 整网结果与 ModelSim 记录一致，PDS 综合资源不变。

注意：

- `.bat` 直接调用 `vsim`，所以 ModelSim 的 `win64` 目录要在 `PATH` 里；否则打开 ModelSim，先 `cd` 到该目录再 `do test_layer_all.tcl`（需要先 `set ROOT_DIR`/`set TARGET_LAYER`）。
- **不要同时跑多个 `.bat`**：它们共用 `rtl_work` 库，会撞 `_opt` 优化库锁，表现为莫名其妙的编译失败。
- 脚本会把 `rtl_pds/data_process/mem_data/*.mem` 拷到 `sim_pds/sim_modelsim/mem_data`，`sim_out/` 下是输出 hex。

## 4. 第二步：PDS 综合 / 布局布线 / 生成码流

1. **删掉作者机器留下的工程锁**（否则 PDS 可能提示工程被占用）：

   ```powershell
   Remove-Item prj_pds\hdmi_loop.pds.lock -ErrorAction SilentlyContinue
   ```

2. 用 PDS 2022.2-SP6.4 打开 `prj_pds/hdmi_loop.pds`。确认：
   - Device：`Logos2 / PG2L200H / -6 / FBB676`
   - Top module：`hdmi_loop`
   - Include 路径：`../rtl_pds/data_process/header`、`../rtl_pds/data_process/mem_data`
   - 约束文件：`hdmi_loop.fdc`（就是刚改好的那份）
   - 综合器路径如果是 `C:/pango/PDS_2022.2-SP6.4/...`，而你的安装目录不同，在工程的 Synthesis 设置里重新选一次。

3. **清一次旧缓存再跑**。`prj_pds/` 里带着作者在 mini 板上跑出来的 `compile / synthesize / device_map / place_route / generate_bitstream` 结果，直接点“生成码流”可能复用旧网表（README 里也记录过 `.fic` 缓存导致上板异常的情况）。
   - 最省事：在 PDS 里用 Clean；或关闭 PDS 后删掉这几个目录下的中间文件（`.adf/.cmr/.fic/.pcf/.prr/.sbit` 等），保留目录本身。

4. 依次执行：**Compile → Synthesize → Device Map → Place & Route → Generate Bitstream**。

5. 结果自检（很重要）：
   - 资源量应与 README 记录接近：**LUT ≈53%、Register ≈33%、DRM ≈63%、APM ≈38%**；
     本机实测（2026-10-29，改造后的工程）：**LUT 51.76%、Register 31.98%、DRM 61.93%、APM 37.70%**，与文档一致；
   - 在 Device Map 的资源树里确认 `u_top_yolo`、`u_lprnet_top`、`u_char_overlay` 下面各层真实展开，**没有整块被优化成 0**；
   - 时序：`pixclk` 约 80MHz、`clk_pe` 约 162MHz，Setup/Hold Slack 为正。
   - 如果 `u_lprnet_top` 资源异常偏小或消失，按 README「PDS 综合与 Debug 经验」处理（显式例化、PAP_MARK_DEBUG、清缓存），这不是本文改动引入的问题。

## 5. 第三步：下载 + 上板

1. 板子上电（12V），接 JTAG 下载器。
2. PDS → Tools → Download，选择 `prj_pds/generate_bitstream/hdmi_loop.sbit`，下载到 SRAM（掉电丢失）；需要固化再走 Flash 流程。
3. 接好 HDMI：PC（1280×720@60）→ 板子 HDMI IN；板子 HDMI OUT → 显示器。
4. 按一下复位键（`rst_n`，C22）。

正常现象：

- 显示器出现 720p 画面（原图 + 检测框 + 车牌字符）；
- **LED0（A20，`led_int`）在识别到字符后常亮**——这是最直接的“LPRNet 出结果”指示；
- **LED1（C18，`ddr_init_done`）在 DDR3 校准完成后亮**——如果不亮，先查 DDR，不用管识别。

> 注：`char_seen_latch` 是锁存型，识别到一次字符后 LED 就一直亮；复位后才清零。

## 7. 排错顺序（按链路从后往前）

| 现象 | 优先检查 |
| --- | --- |
| 显示器完全没信号 / 全黑 | MS7210 没配置成功：`hd_scl`=K22、`hd_sda`=K23 是否接反；`rstn_out`(G25) 是否有 1ms 后释放；`pixclk_out`(T24) 是否有 74.25MHz；输入是否真的是 720p60 |
| 有画面但没有框 | YOLO 没出结果：先确认输入是 720p60；再调 `CONF_THRESH`（`8'h40`，可试 0x20/0x60）；确认 `u_top_yolo` 各层资源正常 |
| 有框但没有字符 | 看 LED0(A20)：不亮说明 LPRNet 链路没出字符。依次看 crop 是否触发（`start_crop_wr/end_crop_wr`）、`lprnet_new_line/lprnet_data_valid`、`lprnet_out_valid`；参考 README「LPRNet 链路观测点」 |
| 框和画面不同帧 / 框错位 | `DDR_READ_START_LINE`（默认 6，第 7 行 layer7 后启动 DDR 读）；`ddr_init_done` 是否亮 |
| 画面撕裂、闪烁 | 多为 box/crop 时序问题，见 `doc/改动.md` 记录；先确认 `MAX_BOX_NUM`=6 与 crop buffer 深度是否匹配 |
| 综合后层级消失 / 上板行为诡异 | PDS 缓存问题，见 README「PDS 综合与 Debug 经验」；先 Clean 再全流程，必要时清 `.fic` |

## 8. 想换模型 / 改参数时

- 重新生成权重头文件和 mem（需要 scipy）：

  ```powershell
  python python_script\CnnHardwareGenerator_pds.py
  ```

  会更新 `rtl_pds/data_process/header/layerN.vh`、`.../mem_data/*.mem`、`conv_data_hex_pds/*.hex`。
- 层间约束（必须满足）：`pe_page_num × cycle_period_cin` 覆盖输入通道；`pe_col_num × cycle_period_cout` 覆盖输出通道；上一层 `PE_COL_NUM` = 下一层 `PE_PAGE_NUM`；上一层 `CYCLE_PERIOD_OUT` = 下一层 `CYCLE_PERIOD_IN`。
- 改完先跑单层 `2_Run_test_layer_run-all.bat <layer>` + `compare_data_pds.py --layer <layer>`，再跑整网，最后再上板。
